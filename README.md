## 3. Setup

```bash
# 1. Clone the cadet-ar-app branch (all result files are included)
git clone -b cadet-ar-app https://github.com/DurgamPoojitha/CADET_Team8.git cadet_ar
cd cadet_ar

# 2. Create a virtual environment (Python 3.10 or later)
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 3. Install pinned dependencies
pip install -r requirements.txt

# 4. Copy the two model checkpoints (NOT in git — too large for GitHub)
#    cp /path/to/best_clean_model.pth  models/best_clean_model.pth
#    cp /path/to/best_fgsm_model.pth   models/best_fgsm_model.pth
```

> [!IMPORTANT]
> Use `opencv-python==4.14.0.94`. The headless variant (`opencv-python-headless`) bundled with some PyPI resolvers omits the Haar cascade object-detection module that the face detector requires.

## 4. Required model files

> [!IMPORTANT]
> `models/results/` (all CSVs, JSONs and figures) and `models/deploy_config.json` are **already committed** in this branch — no manual action needed for them.  
> Only the two large checkpoint files must be copied manually.

After cloning, copy the two checkpoint files into `models/`:

```bash
# Copy from wherever you have them (Kaggle output, shared drive, etc.)
cp /path/to/best_clean_model.pth  cadet_ar/models/best_clean_model.pth
cp /path/to/best_fgsm_model.pth   cadet_ar/models/best_fgsm_model.pth
```

The app will show a clear error on startup if either `.pth` file is missing.  
`deploy_config.json` is already in the repo — do not overwrite it unless you have a newer version.

The checkpoints are loaded with `torch.load(..., weights_only=False)` via `model_state_dict` key (extra keys such as `meta` are ignored).

## 5. Run the app

```bash
source venv/bin/activate
streamlit run app.py
```

The app opens at **http://localhost:8501**.

On first start the two models are warmed inside `@st.cache_resource`; a "Loading models…" notice is shown until they are ready. Subsequent page navigations reuse the cached models at zero cost.

## 6. Pre-compute sample cache

Pre-computing lets the Analyse page load sample results instantly without running the model live during a demo.

```bash
source venv/bin/activate
python make_samples.py
```

This will:
- Run `analyze_video()` over every `samples/*.mp4` for both models (FGSM and Clean) with the stress test enabled.
- Save 16 face-crop JPGs, 6 Grad-CAM overlay JPGs, and a face-box frame per clip/model under `samples/cache/<clip>/<model>/`.
- Write the full result metadata to `samples/cached_results.json`.
- Print a summary table: clip, ground truth, model, P(fake), verdict, and whether the prediction was correct.

Regenerate whenever checkpoints or thresholds change.

## 8. CPU performance benchmarks

Measured on an Apple M-series CPU (single-threaded PyTorch, no GPU):

| Stage | Time |
|---|---|
| Model warm-up (first load) | ~0.2 s |
| Face detection (16 frames) | ~0.5 s |
| JPEG compression roundtrip | ~0.1 s |
| Forward pass (EfficientNet-B1 × 16 frames + LSTM) | ~10 s |
| Grad-CAM backprop (6 frames) | ~25 s |
| FGSM stress pass | ~10 s |
| **Total with Grad-CAM + stress** | **~45 s** |
| **Total without stress** | **~35 s** |

> [!TIP]
> For a live demo with minimal wait, select a sample clip (pre-computed, loads instantly) and only run the uploader path on a short clip (≤10 s).

## 9. Plugging in image\_inference.py

A teammate can add single-image deepfake detection by creating `cadet_ar/image_inference.py` and implementing:

```python
def analyze_image(path: str, model: str = "fgsm") -> dict:
    """
    Parameters
    ----------
    path  : absolute path to a JPEG/PNG image file
    model : "fgsm" or "clean"

    Returns
    -------
    dict with EXACTLY this schema (all keys required):
    {
        "verdict":     str,    # "authentic" | "manipulated" | "inconclusive"
        "probability": float,  # P(fake) in [0, 1]
        "raw_logit":   float,  # pre-sigmoid logit
        "threshold":   float,  # decision threshold used
        "T":           float,  # temperature used
        "stages": {
            "face_detect":  float,   # ms
            "forward_pass": float,   # ms
            "gradcam":      float    # ms
        },
        "evidence": {
            "crop_path":       str,    # path to face crop JPG
            "face_box":        list,   # [x, y, w, h] or None
            "used_fallback":   bool
        },
        "explain": {
            "gradcam_path":    str    # path to Grad-CAM overlay JPG
        },
        "model": str               # "fgsm" | "clean"
    }
    """
```

The Analyse page will automatically detect and use `image_inference.py` when an image file (`.jpg`, `.jpeg`, `.png`) is uploaded.

## 10. Filling in the Image tab (teammate guide)

The Method and Results pages each have a **Video** tab (fully working) and an
**Image** tab (coming-soon panel). Here is exactly what to do to replace the
placeholder with real content.

### Step 1 — Put result files in the right place

```
cadet_ar/
└── models_image/
    └── results/           ← create this directory
        ├── *.csv / *.json ← your image-model metric files
        └── figures/       ← your PNG figures
```

As soon as `models_image/results/` exists and contains at least one file,
the coming-soon panel disappears automatically on the next app start.

### Step 2 — Edit the two component files

| File | What to edit |
|---|---|
| `components/image_method.py` | Replace the `render()` body with your image pipeline description, using the same `st.markdown` / `st.columns` calls as `components/video_method.py`. |
| `components/image_results.py` | Replace the `render()` body with real tables, charts and figures, following the same patterns as `components/video_results.py`. Read all numbers from files in `models_image/results/` — do not hardcode. |

Both files have a `_results_available()` guard at the top. Leave that guard in
place so the coming-soon panel is shown automatically on machines that do not
have the result files yet.

### Step 3 — Implement analyze_image()

`image_inference.py` (already in the repo) must expose:

```python
def analyze_image(path: str, model: str = "fgsm") -> dict:
```

The return dict **must use the same schema** as `analyze_video()`:

```
verdict, probability, raw_logit, threshold, T,
stages, evidence, explain, stress, model
```

The Analyse page will call `analyze_image()` automatically when a `.jpg` /
`.jpeg` / `.png` file is uploaded.

> [!IMPORTANT]
> Never invent numbers or model names in the Image tab. Everything shown must
> come from real evaluation files in `models_image/results/`.

## 11. Architecture overview

| Component | Detail |
|---|---|
| Backbone | EfficientNet-B1 (pretrained weights disabled; checkpoint supplies all weights) |
| Temporal head | Single-layer LSTM (hidden=256) over 16 uniformly sampled frames |
| Face detection | OpenCV Haar cascade (`haarcascade_frontalface_default.xml`) |
| Face crop | Largest detected face, expanded by factor 1.3; central-crop fallback |
| Compression | JPEG quality 95 roundtrip per frame (matches C23 training distribution) |
| Normalisation | ImageNet mean/std: `[0.485,0.456,0.406]` / `[0.229,0.224,0.225]` |
| Calibration | Temperature scaling (T_clean=0.554, T_fgsm=0.950) |
| Explainability | Grad-CAM on `model.feature_extractor[0][-1]` (last EfficientNet block) |
| Adversarial | FGSM (ε=4/255) single-step stress pass on clean input tensor |
| Thresholds | P(fake) ≥ 0.316 → manipulated (Clean); ≥ 0.513 → manipulated (FGSM) |
